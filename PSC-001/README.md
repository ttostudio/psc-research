# PSC-001｜確定前に同じバージョンの確認が必要か

- 対象: PSC v1 マスタープラン §3.2 **SEC-004 禁止された状態遷移の排除**。
- 検証水準: **L2**。有限モデルを実装し、列挙検査を通過。外部の証明器での証明、独自言語での実装、実アプリの統合検証は未実施。先行する予備実験とは別に、PSC の計画に沿って実施した。
- 実行日時: `executed-at-utc.txt`。実行環境: Python 3.12.14、標準ライブラリのみ。課金・投稿・外部接続なし。

## 仮説・仕様

机上の文書編集器。状態は `(phase, revision)`。初期状態は draft / 0。バージョンは 0、1、2 に限定。イベントは revise、review、finalize とバージョン指定（指定なし、0、1、2）の全組合せとする。以下だけが状態を変える。その他の組合せは元の状態を返す。

| 元の状態 | 入力 | 結果 |
| --- | --- | --- |
| draft / r または reviewed / r、かつ r < 2 | revise、バージョン指定なし | draft / r+1（確認を取り消す） |
| draft / r | review(r) | reviewed / r |
| reviewed / r | finalize(r) | final / r |
| final / r | すべて | 変化なし |

検証する不変条件: reviewed または final であれば、現行バージョンを編集した後の、そのバージョンに対する review が履歴にある。さらに final は後続のどのイベントでも変更されない。正しい順序で確定できることも、実装が単にすべて拒否しているわけではないことの確認として検査する。

## 再現

```sh
python3 -B check.py
sha256sum -c SHA256SUMS
```

- `model.py`: 副作用を持たない遷移関数。
- `check.py`: 別に記述した許可関係と全状態・イベント組合せを比較し、到達可能なグラフを探索して履歴を伴う不変条件を確認。
- `results.json`: 実行結果。9 状態 × 12 イベント値の **108 組**すべて期待値と一致。10 組が状態変更、98 組が変更なし。到達可能な履歴付き状態を全探索し、不変条件に反する状態や遷移はなかった。7つの読みやすい個別シナリオも合格。組合せの数は脆弱性・攻撃・バグの数ではない。
- `optimized-rejection.txt`: アサーションが無効になる Python `-O` 設定で検証が起動せず、成功結果を生成しないことを別途確認。

入力は内部の型付き値。外部入力の解析、レビュー者の権限、複数利用者、並行処理、保存・再起動、ネットワーク、バージョン上限外、第三者システムは対象外。上限を含む仕様は **この実験の仮定** で、製品や計画全体の契約ではない。テストと実装の双方が同じ仕様の誤りを含む可能性は残る。形式的な証明や製品の安全性は主張しない。

次は仕様・前提を独立レビューし、同じ遷移表を別の実装で表現し、同じケースと照合する。表現方法の違いを、独自言語の型と意味論の設計に役立てる。証明器は別段階で選定し、L3 を名乗る場合は対象性質・仮定・検証器・再現ログを固定する。
