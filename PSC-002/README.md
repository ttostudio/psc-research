# PSC-002｜同じ下書きを別々に編集したとき、片方が黙って消えないか

- PSC v1.0 フェーズ1、SEC-004 の小さな追加モデル。PSC-001 のレビュー規則を直接変更しない。
- 仮説: 保存時に「編集を始めたバージョン」と現在のバージョンを一つの原子的な操作で比較すれば、同じ古い下書きに基づく後着の全置換を、上書きではなく再確認が必要な競合として返せる。
- 比較: 無条件に置換する保存と、期待バージョン一致時のみ置換する保存。操作を実行する順序以外の入力を揃える。
- 成功条件: 現行バージョンに基づく保存は適用、古いバージョンに基づく保存は内容・バージョンを変えず競合を返す。競合後、改めて最新内容を取り込んだ保存が適用できる。比較側で両方受理される具体例と、そのときどちらの内容が残るかも測る。

## 結果（L2）
初期バージョン4通り × 異なる編集の組3通り × 到着順2通りで24条件、各条件で2方式を実行（計48実行）。無条件保存では24/24で先着編集が消えた。条件付き保存では24/24で後着保存が競合と明示され、先着編集は残った。編集者が最新内容にもう一方の変更を反映して再送すると24/24で両方が残った。これは件数の推定でも、本番で防いだ障害の数でもない。

再現（標準ライブラリのみ）:
```sh
cd PSC-002
python3 -B check.py | diff -u results.json -
python3 -B -O check.py | diff -u results.json -
sha256sum -c SHA256SUMS
```

実行時刻・Pythonバージョン・JSONログは同梱。限界: 1文書・2編集・直列化された到着順のみ。競合検出と更新が実装でも原子的である必要がある。このテストは並列処理、DB、永続化、マージの妥当性、Elmでの動作、形式証明を検証していない。異なる対象の独立検証は未実施。次は、並行動作を仮定せずに再現する実装テストの設計と、PSC-001仕様のElm照合に戻る。
